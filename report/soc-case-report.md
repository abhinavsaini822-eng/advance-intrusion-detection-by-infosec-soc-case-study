# SOC Case Report – Suspicious AV Detection

## 1. Incident Overview

A critical antivirus alert was generated by Cisco AMP after a malicious file was detected on an employee's workstation. The file could not be cleaned and was assigned a malicious disposition.

The investigation identified the file as a malicious Microsoft Excel spreadsheet associated with TrickBot.

**Incident classification:** Malware Infection – Trojan  
**Affected asset:** Employee workstation  
**Affected users:** 1 identified user

---

## 2. Indicators of Compromise (IOCs)

## 3. Investigation and Analysis

### 3.1 Initial Alert

Cisco AMP generated a critical antivirus alert for a file on an employee's workstation. The file was marked as malicious and could not be cleaned.

The MD5 hash was extracted and submitted to VirusTotal for further investigation.

### 3.2 VirusTotal Detection Analysis

VirusTotal identified the file as malicious, with 41 out of 64 antivirus engines detecting it as a threat.

Multiple vendors classified the file as a Trojan, downloader, or malicious Microsoft Office file.

The file was identified as a Microsoft Excel spreadsheet associated with TrickBot.

### 3.3 Behavioral Analysis

VirusTotal sandbox analysis revealed several suspicious activities:

- The Excel workbook contained a hidden worksheet.
- The file appeared to construct and use the Windows API function `URLDownloadToFileA` to download another file.
- The workbook appeared to execute the downloaded file through an Excel `EXEC` function.
- The process `C:\Windows\System32\rundll32.exe` was identified in the behavior report.
- HTTP communication with an external server was observed.

These findings indicate that the spreadsheet was capable of downloading and executing additional malicious content.

**Note:** These behavioral observations are from VirusTotal sandbox analysis and should not automatically be treated as confirmed activity on the employee's actual workstation.

### 3.4 SIEM Investigation

A hash-based search was performed in the SIEM to determine whether other endpoints were associated with the same malicious file.

No additional matching artifacts were identified.

Based on the available SIEM results, one employee workstation was identified as affected.

**Investigation scope:** No additional endpoints identified using the investigated MD5 hash. This does not rule out other activity involving different indicators.

---

## 4. Attack Details

The user received a suspicious phishing email containing a malicious Excel spreadsheet. After downloading the file, the user enabled its macros, allowing the embedded malicious code to execute.

The malware demonstrated downloader behavior, suspicious external HTTP communication, and execution involving the legitimate Windows utility `rundll32.exe`.

The incident is classified as a Trojan infection associated with a malicious Excel spreadsheet.

---

## 5. Remediation Steps

The following remediation steps were specified in the exercise:

1. **Reset network credentials:** Contact the help desk and reset the affected user's network credentials as a precaution against potential credential compromise.
2. **Contact the impacted user:** Contact the employee via phone to gather information about the incident and understand how the file was received and executed.
3. **Confirm device ownership:** Determine whether the affected workstation is company-issued or personally owned under the organization's BYOD policy.
4. **Network isolation:** Disconnect the affected workstation from the company network to contain the incident.
5. **Wipe and reimage:** Wipe and reimage the affected machine, if possible, to remove the compromised system state.

---

## 6. Conclusion

The investigation identified a malicious Excel spreadsheet associated with TrickBot that was responsible for the malware incident.

VirusTotal analysis provided evidence of malicious downloader behavior, suspicious process execution, and external network communication.

The SIEM investigation did not identify additional endpoints associated with the same file hash. The investigation therefore identified one affected user workstation.

The recommended remediation actions include credential reset, user communication, device ownership verification, network isolation, and system reimaging.
